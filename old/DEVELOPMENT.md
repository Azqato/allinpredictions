# Development

All initial development of this project was done in English via [Codex CLI](https://developers.openai.com/codex/cli/) over a weekend.

## Requirements
- Python 3.9+
- `pip install -r requirements.txt`
- Network access that allows outbound HTTPS requests

## Setup
1. Install dependencies:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```
2. Configure secrets:
   ```bash
   cp .env.example .env
   # Edit .env and paste your various API keys
   ```
3. Ensure `ffmpeg` is installed (required for speaker embedding extraction), e.g. `brew install ffmpeg`.

## Generated artifacts (not tracked)
- Audio, raw feeds, processed transcripts, speaker profiles, and model outputs live under `data/` and are gitignored (`data/audio`, `data/raw`, `data/processed`, `data/speakers`).
- Local model folders under `pretrained_models/` are also ignored.
- Regenerate these per the commands below; avoid committing large artifacts to keep the repo lean.

## Usage
1. Fetch + parse the RSS feed:
   ```bash
   python3 scripts/all_in_downloader.py  # uses yt-dlp to attach YouTube URLs
   ```
   This stores the raw feed at `data/raw/all_in_feed.xml` and normalized metadata at `data/processed/all_in_episodes.json` (includes inferred filenames for every enclosure).

2. Download audio (skip/limit as needed):
   ```bash
   python3 scripts/all_in_downloader.py --download-audio --download-limit 3
   ```
   - Set `--download-limit` to control how many episodes you grab (omit it for the full archive).
   - Use `--audio-dir` to change the destination (defaults to `data/audio/all_in`).

3. Re-run the command any time; existing MP3s are skipped automatically and only new episodes download.

With the archive mirrored locally, we can feed the MP3s into Whisper/WhisperX (for diarized transcripts) and then progress into the prediction-mining stages.

## Transcription

Multiple ASR/transcription providers were tested (AssemblyAI, Deepgram, OpenAI, Speechmatics) and I subjectively found that Speechmatics had the right balance of low word error rate, solid diarization, and the ability to process long episodes.

1. Ensure you have `.env` populated with `SPEECHMATICS_API_KEY` and at least one MP3 in `data/audio/all_in`.
2. Transcribe a specific episode:
   ```bash
   python3 scripts/transcribe_speechmatics.py --episode-id ALLIN-E010
   ```
3. Or batch everything you’ve downloaded (add `--limit` for smoke tests, `--max-concurrency` to tune parallelism; defaults to 10 simultaneous jobs):
   ```bash
   python3 scripts/transcribe_speechmatics.py --all --limit 2
   ```
4. Outputs land in `data/processed/transcripts_X/<episode-id>/`:
   - `speechmatics_raw.json`: untouched API response
   - `segments.json`: speaker-labeled segments with timestamps
   - `transcript.txt`: human-readable transcript
   - `metadata.json`: summary metadata for orchestration

## Speaker Labeling
1. Generate canonical embeddings for known hosts (once per speaker). For example, episode `ALLIN-E000` uses labels `A`, `B`, `C` for Jason/Chamath/Friedberg:
   ```bash
   python3 scripts/build_speaker_profiles.py --episode-id ALLIN-E000 \
     --assign A=jason --assign B=chamath --assign C=friedberg
   ```
   This produces `.npy` files under `data/speakers/` and records their paths inside `config/speakers.yaml`.
   - Add `--debug` to dump the sampled audio clips for each speaker under `data/speakers/debug/<episode>/<speaker>/` for manual review.
2. Map diarization labels in any episode (or across the entire archive) to the canonical roster:
   ```bash
   # Single episode
   python3 scripts/assign_speakers.py --episode-id ALLIN-E000

   # All transcripts, six parallel jobs (skips if transcript_named.txt already exists)
   python3 scripts/assign_speakers.py --all --max-concurrency 6
   ```
   - Defaults require ≥3 s segments and cosine similarity ≥0.97; adjust via `--min-duration` / `--threshold`.
   - Pass `--transcription deepgram` or `--transcription openai` to label diarized segments generated by those pipelines.
   - Matched segments gain `canonical_speaker` metadata and a human-readable transcript at `transcript_named.txt`.
   - If a label fails the threshold, it stays as `Speaker X` and is logged in `speaker_map.json` for manual review; rerun with `--force` to overwrite.

Run `assign_speakers.py` after every new transcription to keep speaker names consistent across the archive. Update `config/speakers.yaml` (or rerun `build_speaker_profiles.py`) whenever you add a new canonical voice.

## Prediction Extraction & Validation
- Extract predictions from transcripts (filters to named speakers) and save to `predictions.json`:
  ```bash
  python3 scripts/prediction_pipeline.py --episode-id ALLIN-E000 --transcription speechmatics
  # Batch
  python3 scripts/prediction_pipeline.py --all --transcription speechmatics --max-concurrency 4
  ```
- Validate predictions with web search + structured output; results go to `predictions_check.json` (skips existing unless `--force`):
  ```bash
  python3 scripts/prediction_pipeline.py --episode-id ALLIN-E000 --transcription speechmatics --validate --validate-concurrency 4
  # limit per episode
  python3 scripts/prediction_pipeline.py --all --validate --validate-limit 5
  ```
- YouTube deep links: downloader fetches full uploads via `yt-dlp` (`@allin/videos`) and attaches `youtube_url` to episodes (code matching supports E1/E001; add overrides in `config/youtube_urls.json` for stragglers). The web UI links prediction timestamps to `youtube_url?t=seconds` and shows a one-time warning; unmatched timestamps show a tooltip.
